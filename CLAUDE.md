# Follow the Rupee: Mumbai Monsoon Roads

Claude Impact Lab Mumbai hackathon, 21 Nov 2026. Two-person team. Full brief: `docs/CHALLENGE.md`,
columns: `docs/DATA_DICTIONARY.md`, ideas and **judging rubric**: `docs/STARTER_IDEAS.md`.
All data in `data/` is synthetic; contractors are fictional.

Goal: show where each ward's road repair money went, whether the fix held, who is responsible,
and where the next rupee should go. Rubric weights: audit accuracy 25%, fair accountability 20%,
budget recommendation 20%, connecting the trail 15%, usability 10%, demo 10%.

## Commands
- Pipeline: `cd pipeline && uv run pipeline next-rupee` builds the next-rupee plan, backtest and `web/public/data/*.json`
  (~40 s); `uv run pipeline trail` writes the complaint trail, `uv run pipeline wards` the ward summaries, `uv run pipeline export` the dashboard views (work orders, ward bundles, map layers), `uv run pipeline all` rebuilds everything in order;
  `uv run pipeline audit` writes flags; `uv run pipeline scorecards [--no-claude]` writes contractor scorecards
  (Claude text needs `ANTHROPIC_API_KEY` in `pipeline/.env`, otherwise a template is used). `uv run pipeline` prints a data summary, `uv run pytest` runs tests, `uv add <pkg>` adds deps.
- Tunable weights and thresholds for the index: `pipeline/src/pipeline/config.py` only.
- Web: `cd web && npm install && npm run dev` → http://localhost:3000
- Web checks: `cd web && npm run lint && npm run build`
- Next.js here is v16; read `web/AGENTS.md` and `web/node_modules/next/dist/docs/` before using APIs.

## Rules for the work
- Every flag, score and recommendation must cite the work-order IDs (or road/complaint IDs) behind it.
- Be fair: adjust for low-lying wards, heavy-rain days (`rainfall_daily.csv`) and big tides before blaming
  a contractor. Normal jobs vary ~20–30% around the rate card, so don't flag that.
- Plain language for citizens and corporators. No accusations, just evidence.
- Deterministic numbers come from pandas; Claude writes the explanations and handles messy text
  (multilingual complaints, social posts). Never let the LLM invent numbers.
- Claude API: `claude-sonnet-5-5` for narration and parsing, `claude-haiku-5-5` for bulk classification.
  Cache LLM outputs to disk so reruns and the demo don't call the API again.
- `ANTHROPIC_API_KEY` goes in `pipeline/.env` (see `.env.example`). Never commit keys.

## Git workflow
Branches (all on GitHub):
| Branch | Who | Purpose |
|---|---|---|
| `prathik/data-models` | Prathik | Pipeline, models, generated data. Work and commit here |
| `noel/dashboard` | Noel | Dashboard UI. Work and commit here |
| `dev` | Both | Integration. Both merge their branch into it; it must build |
| `main` | Both | Demo and judging branch. Only receives `dev` at sync points (12:30, 14:30, 15:30) |

Rules:
- One-time per clone: `bash scripts/setup-collab.sh` (turns on the sync report, uses merges not rebases).
- **Start of every work block:** `git fetch`, then `scripts/sync.sh`. It prints what is on `origin/dev` that you do not have,
  who owns each changed area, contract/dependency/overlap warnings, and the commands to keep or discard parts of it.
  Read `SYNC_REPORT.md`, then merge: `git merge origin/dev` (or `git merge --no-commit --no-ff origin/dev` and
  `git checkout HEAD -- <file>` for any file you want to discard). Pulls also write `SYNC_REPORT.md` automatically.
- **Ship to dev:** commit, `git merge origin/dev` into your branch, run the checks (pipeline: `uv run pytest`;
  web: `npm run lint && npm run build`), then `git push origin <your-branch>` and merge into `dev`
  (`gh pr create --base dev --fill` then `gh pr merge --merge`, or `git switch dev && git merge --no-ff <your-branch> && git push`).
- **Leave a note:** add an entry at the top of `HANDOFF.md` whenever you push something the other person should know about
  (contract change, new data file, a changed number, something they must do). Keep it short and factual.
- **Ship to main:** only from `dev`, only when `dev` builds: `git switch main && git merge --no-ff dev && git push`.
- Never force-push `dev` or `main`. Never commit directly to them except merges.
- Stay in your own folders (see Ownership). If you must touch the other person's files or the contract, say so in `HANDOFF.md`.
- Small commits with clear messages.
